Part 2

Pre Image Alignment and Stacking

Each set of glass plates has three grayscale exposures: BGR from top to bottom. I split the top third into blue, the middle third into green, and the bottom third into red, but noticed that not all 3 images were always the same size. As a result, I decided to resize the green and red images to be the same size as the blue image.

Here is an example of what the train set looked like split into its 3 separate parts:

I kept the blue image fixed, and tested horizontal and vertical displacements for the green and red images. At each position, I took an interior crop from the green image and compared it with the same area of the blue image. The same activity was separately performed for the red image against the blue image as well. I chose to use euclidean distance (L2) as the metric to compare each pixel. The lowest L2 score gives the offset for that corresponding image.

L2 = sqrt(sum over the crop of (blue image - shifted image) squared).

I chose to score only the interior because I didn't want the plate borders, which looked different for each image, to affect the L2 score. The reported offsets describe where the crops were sampled relative to blue, but the final placement uses the opposite sign.

Two methods were used to align images: single-scale alignment and multi-scale pyramid alignment.

Single-scale alignment

The single-scale alignment method was to be tested on 3 images: train, woman's portrait, and building. Here is a breakdown of the steps I took to be able to perform the alignment:

  1. Split the images

    2. I read the image set in grayscale and then started by splitting the blue image using blue = img[0:int(total_rows/3)]. I took the next two thirds for green and red and used cv2.resize to match their dimensions to blue.

  2. Subsample for speed

    3. The train and the woman's portait were high resolution images and an exhaustive search would take a long time on the original images so I decided to subsample for speed. I used blue_subsampled = blue[::2, ::2] to keep only every other row and column for the blue image, and then did the same for the green and the red. Each L2 comparison uses about one quarter of the original pixels, which saved time.

  3. Set the search region

    4. The search radius is estimated_border_size = int(min(height, width)*0.10) and the interior crop size is size = min(height, width)-estimated_border_size*4. This makes it so that it stays away from the plate borders. The x and y loops test offsets from the negative radius to just below the positive radius.

  4. Score each shift

    5. The blue image stays fixed and I compare it with the shifted green and red crops using np.linalg.norm(blue_img_crop.astype("float32") - green_img_crop.astype("float32")) and the same for the red. I keep the lowest L2 scores for each.

  5. Return to full resolution

    6. I multiply each offset by two since I had originally subsampled the images by taking every other row and column only: new_green_image_offset = np.array(green_image_offset)*2

Multi-scale pyramid alignment

Since the single-scale alignment method can be very time consuming, I also tested the multi-scale pyramid alignment method. This method was to be tested on 18 images, and a few additional plates of my choosing. I chose the beans, siren, and sculptures images. Here is a breakdown of the steps I took to be able to perform the alignment:

  1. Build the pyramid

    2. I start each channel list with the full-size image. The downsample loop adds cv2.pyrDown(blue_img) and does the same for green and red. It smooths before halving each dimension. For each trial, I change the amount of times I downsample the image, but in my final trial where all of my images are aligned well, I downsample 3 times when it is a high resolution image, for example when max(blue_img.shape) is over 1000 pixels, and only one time when its smaller.

  2. Search the smallest level

    3. The initial sweep is xy_sweep = int(min(height, width)*0.10). The green and red estimates start at [0, 0]. I used the same float32 L2 comparison as used in the single-scale alignment method.

  3. Work back up the pyramid

    4. The loop for i in range(len(blue_pyramid)-1, -1, -1) goes toward full resolution. I added a local correction and doubled the estimate for the next level with old_green_image_offset = new_green_image_offset*2. The local sweep is 10 pixels at small levels and 3 pixels at larger levels. The next crop size is int(min(height, width)*0.6).

  4. Adjust intensities for matching

    5. In trial 1-3 this was not performed, but in trial 4 and 5 I tested the effect of normalization using cv2.normalize. In trial 5, I tested brightness adjustment by taking the mean brightness of the blue image and moving the green and red means toward the blue mean with cv2.convertScaleAbs.

  5. Save the image

    6. I place blue at the centre of a padded canvas and stack green and red using the opposite of their measured crop offsets. I left the scan borders in the output.

Limitations

I only estimated x and y shifts. Movement between exposures, plate damage, and differences in channel brightness can still leave colour fringes. The output also keeps the scan borders. There were no ground-truth offsets for me to calculate a numerical alignment error.
