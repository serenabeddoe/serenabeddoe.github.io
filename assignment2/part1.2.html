Part 1.2: Finite Difference Operator

I implemented 2D convolutions using 4 for loops and 2 for loops and 3 different filters: Dx, Dy, and a 9x9 box filter.

Here is a breakdown of the steps I took to be able to perform the convolutions:

  1. Padding the image

    2. I padded the image with zeros (black) so the output would come out the same size as the input. The padding on each side is half the filter size, topbot_pad = int(((filter.shape[0]-1)/2)) and leftright_pad = int(((filter.shape[1]-1)/2)), and I applied it with np.pad(array=image, pad_width=padding_size, mode="constant", constant_values=0).

  2. Flipping the filter

    3. Convolution applies the filter flipped, so I used np.flip(filter) to flip it.

  3. Convolution with 4 for loops

    4. The outer two loops go over every pixel of the original image, and the inner two loops go over every entry of the flipped filter. Each output pixel is a running sum, sum += flipped[k][l] * padded_image[i+k][j+l], which I then save with output_image[i][j] = sum.

  4. Convolution with 2 for loops

    5. I kept the two outer loops, but replaced the inner two loops from the 4 for loop version. For each pixel I take the section of the padded image that the filter covers, group = padded_image[i:i+flipped.shape[0], j:j+flipped.shape[1]], and then multiply it by the flipped filter and add everything up with np.sum(group * flipped).

  5. Filtering the photo

    6. I read my photo in grayscale with cv2.imread(image, cv2.IMREAD_GRAYSCALE) and made the three filters dx = np.array([[1,0,-1]]), dy = dx.reshape(-1,1), and the box filter nine = np.ones((9,9)) / 81.0. Dx and Dy produce negative values, so before saving those outputs I rescaled them to 0–255 by shifting with image - image.min() and scaling with 255 * image / image.max(). The box filter blurs the image, Dx picks up vertical edges, and Dy picks up horizontal edges.

  6. Comparing with scipy

    7. In order to compare accurately, I made sure to treat boundaries the same for the two-loop, four-loop, and scipy versions. I padded all of them with zeros (black) and made sure the outputs were all the same size by using these scipy parameters: boundary="fill", fillvalue=0, and mode="same". I ran the same filters through signal.convolve2d(grayscale_image, dx, mode="same", boundary="fill", fillvalue=0) and checked each result against mine with np.allclose(output_image_2_dx, scipy_dx). All three filters returned True for both of my versions, meaning the outputs were the same. Padding the images with zeros resulted in dark borders around the box-filtered images and bright lines along the borders of the Dx and Dy outputs.

Filter4 For Loops2 For LoopsScipy

Dy3.709 seconds8.764 seconds0.034 seconds

The runtime was fastest for the SciPy versions because the function runs in compiled C, whereas the four-loop and two-loop versions run in interpreted Python (adds overhead on every step). The 4 for loop version was the slowest by far with the 9×9 box filter, since a bigger filter means more multiplications per pixel, each done one at a time in Python. The 2 for loop version took about the same time regardless of the filter, because its runtime mostly comes from calling NumPy once per pixel, not from the filter size. This is also why the 4 for loop version was faster than the 2 for loop version for the small Dx and Dy filters.
